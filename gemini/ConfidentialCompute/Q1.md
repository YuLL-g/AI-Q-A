satp和hgatp都是 hs-mode的salus管理的吗，他们具体有什么区别？
---

**是的，您的判断非常准确！在 CoVE 架构中，`satp` 和 `hgatp` 这两个寄存器都是由运行在 HS-mode 的 Salus (TSM) 独家管理和直接读写的。**

但是，它们服务的对象、生效的时机以及在机密计算中扮演的安全角色截然不同。

用一句话概括它们的区别：**`satp` 是 Salus 管好“自己”的内部地图，而 `hgatp` 是 Salus 用来管死“别人（虚拟机）”的外部物理枷锁。**

以下为您深度对比这两个寄存器的具体区别：

---

### 1. `satp` (Supervisor ATP) —— Salus 的“自用近视镜”

* **全称**：监管者地址转换与保护寄存器。
* **生效时机**：当 CPU 处于 **`V=0`（虚拟化关闭）**，即正在执行 Salus 自己的代码（HS-mode）时生效。
* **转换层级**：**第一阶段（Stage-1）转换**。
* **核心功能**：
  * 它负责将 Salus 代码里写的**虚拟地址 (VA)** 转换为**系统真实的物理地址 (SPA)**。
  * 在 Salus 项目中，为了极简和安全，Salus 会配置一个 `satp`，建立一张 **1:1 恒等映射（VA = PA）**的页表。
  * **既然是 1:1，为什么还要用 `satp`？** 根本目的是为了利用页表自带的**内存保护位（R/W/X）**。Salus 把自己存代码的内存页设为“只读+可执行”，把存数据的内存页设为“可读写+不可执行”。这样万一 Salus 内部有代码逻辑漏洞，黑客也无法执行缓冲区溢出攻击。
* **受众**：只对 Salus 自己的代码有效。

---

### 2. `hgatp` (Hypervisor Guest ATP) —— 给虚拟机戴上的“VR眼镜”

* **全称**：Hypervisor 客体地址转换与保护寄存器。
* **生效时机**：当 CPU 处于 **`V=1`（虚拟化开启）**，即正在运行宿主机（HostVM/Linux）或机密虚拟机（TVM）时生效。
* **转换层级**：**第二阶段（Stage-2）转换**。
* **核心功能**：
  * 它负责将虚拟机自以为是的**客体物理地址 (GPA)** 强制转换为**系统真实的物理地址 (SPA)**。
  * 虚拟机（比如 Linux）以为自己在直接读写物理内存，但实际上，每一次物理访存指令，都会被硬件截获，并扔进 `hgatp` 指向的第二阶页表里再“翻译”一次。
  * **特殊字段 (VMID)**：`hgatp` 寄存器里不仅有页表地址，还有一个非常关键的 **14位 VMID（虚拟机 ID）** 字段。Salus 给 HostVM 分配 `VMID=1`，给 TVM 分配 `VMID=2`。
* **受众**：只对下面运行的 VS-mode 虚拟机有效，对 Salus 自身无效。

---

### 💡 核心对比总结表

| 对比维度 | `satp` (在 HS-mode 中使用) | `hgatp` (由 HS-mode 配置，给 VS-mode 用) |
| :--- | :--- | :--- |
| **通俗比喻** | Salus 自己的内部安全工作手册 | 强加给所有虚拟机的“物理隔离沙盒” |
| **CPU 标志位** | **V = 0** 时硬件自动查它 | **V = 1** 时硬件自动查它 |
| **地址转换路径** | 虚拟地址 (VA) ➡️ 系统物理地址 (SPA) | 客体物理地址 (GPA) ➡️ 系统物理地址 (SPA) |
| **页表模式(Sv48)**| `Sv48` (普通的 48 位虚拟空间) | `Sv48x4` (物理地址空间通常更宽广，多扩展2位) |
| **是否包含 VMID**| 否（包含 ASID，用于区分普通进程） | **是**（包含 VMID，用于区分不同的虚拟机） |
| **在 CoVE 中的作用**| 保护 Salus 自己的代码不被自身 Bug 篡改 | 彻底斩断 HostVM 偷窥 TVM 内存的可能性 |

### 场景还原：Salus 是怎么玩转这两个寄存器的？

假设系统此刻在运行 Salus，准备切换去运行机密虚拟机（TVM）：

1. Salus 此时在 HS-mode（`V=0`）。CPU 取指令、存取变量，全都在查 **`satp`**。
2. Salus 准备好 TVM 的上下文后，Salus 将 TVM 专属的第二阶段页表物理基地址写入 **`hgatp`**，并设置 `hgatp` 中的 `VMID=2`。
3. （此时 `hgatp` 还没生效，因为 `V` 还是 0）。
4. Salus 执行 `sret` 指令，硬件瞬间将 CPU 标志位 **`V` 设为 1**，进入 VS-mode。
5. 从这一纳秒开始，**`satp`** 暂时对 CPU 隐身了（确切地说，TVM 内部有了它自己的 `vsatp`），而 **`hgatp`** 瞬间被硬件激活，像一张巨大的铁网一样罩在了 TVM 的头上，接管了它所有的物理地址访问请求。
